# 펨코 패션 브랜드 필터 — 크롬 확장 프로그램 설계 (v1)

작성일: 2026-11-02

## 1. 의도와 이유

에펨코리아 패션 게시판(`https://www.fmkorea.com/fashion`)에서 브랜드는 공식 이름이 아닌 다양한 별명으로 언급된다.

- 스테디에브리웨어 → 스테디, 스에웨, SEW, 스웨에, 스웨에에에엑 …  검색 한 번으로 착샷을 다 볼 수 없다.
- 어나더오피스 → "목동" (과거 이슈에서 유래). 새로 온 사람은 이 사실을 알 수 없다.
- 파프터, 퍼스트플로어(퍼플) 등 CS 불만 글이 많은 브랜드는 보고 싶지 않은 사용자가 있다.
- "파프"(PAF)를 찾으면 "파프터"가 섞여 나와 `파프 !파프터`처럼 매번 수동 제외를 해야 한다.

**목표 경험:** 타이핑 없이 클릭만으로 "스테디에브리웨어 + 어나더오피스, 착샷 탭" 같은 조건을 고르면 그 브랜드 글이 별명과 상관없이 한 목록에 모여 보이고, 사용자가 고른 브랜드는 어디서도 보이지 않는다.

크롬 웹스토어에 공개 배포한다.

## 2. 범위

이 프로젝트는 두 부분 중 **(1) 크롬 확장 프로그램**이다.

| | 내용 | 이번 범위 |
|---|---|---|
| (1) 확장 프로그램 | 팝업 UI, 브랜드 검색/합치기, 숨기기 | ✅ |
| (2) 사전 파이프라인 | 주기적 수집 → 토큰화 → 사전 매칭 → 수기 확인, 크라우드소싱 분류 | ❌ (아이디어만 기록, §9) |

### 목표
- 사전(브랜드 → 별명 목록) 기반의 클릭형 브랜드 선택
- 여러 브랜드 동시 선택 시 **합집합(OR)** 결과를 한 목록으로
- 카테고리(탭) 지정: 착샷, 질문, 후기 등
- 사용자가 자유롭게 지정하는 숨김 브랜드
- 사전 갱신 시 확장 프로그램 재배포 불필요

### 비목표
- 사전 자동 수집/갱신 (2단계)
- 사용자 별명 제보/크라우드소싱 UI (2단계)
- 중앙 서버/색인
- 모바일 펨코, 패션 외 게시판

### 안티골 (돌아가도 실패인 것)
- 펨코 보안 시스템에 사용자 계정·IP가 차단되게 만드는 요청 패턴
- 사용자가 아무것도 고르지 않았는데 글이 숨겨지는 것 (기본 숨김 없음)
- 펨코 원래 화면을 크게 망가뜨리거나 느리게 만드는 것
- 사용자 데이터를 외부로 전송하는 것 (사전 JSON 다운로드 외 네트워크 없음)

  ID는 변할 수 있으므로 하드코딩 대신 사전 JSON에 넣는다.
- **검색 URL**: `https://www.fmkorea.com/search.php?mid=fashion&search_target=<대상>&search_keyword=<검색어>`
  대상: `title_content`, `title`, `content`, `comment`, `nick_name`.
- **검색 문법** (사용자 확인):
  - 띄어쓰기 = **AND**
  - `!단어` = 제외 (`파프 !파프터` 동작)
  - `|` (OR) **동작 안 함** → 별명별 개별 검색 후 합쳐야 함
  - 정규식/반복(`+`) 미확인, 동작하지 않는다고 가정
- **목록 HTML**: 글 하나 = `<tr>`. `td.cate > a`(탭명, href에 `category=<ID>`), `td.title > a[href="/<문서번호>"]`(제목), `a.replyNum`(댓글 수), `td.author`, `td.time`(오늘 글은 `HH:MM`, 이전은 `MM.DD`), `td.m_no`(조회, 추천). 공지 행은 `tr.notice`, 광고 행 존재. 페이지 이동은 `page=<n>`.
- **보안 시스템**: 짧은 시간에 쿠키/JS 없는 요청이 몰리면 HTTP 430 + JS 확인 페이지로 차단. 차단은 수 분 이상 지속.
- **미확인**: `search.php`에 `category=` 파라미터를 함께 줄 때의 동작(테스트가 차단과 겹쳐 결과 불명).

## 4. 사용자 경험

### 4.1 팝업 (툴바 아이콘 클릭)
확정 시안: `.superpowers/brainstorm/*/content/popup-v3.html` (칩 그리드 + 보기/숨기기 탭).

- 상단: 제목 "패션 브랜드 필터", 사전 버전/갱신일 표시
- **모드 탭**: `보기` | `숨기기 · N` (N = 숨긴 브랜드 수)
- **보기 탭**
  - 카테고리 칩(단일 선택): 전체, 착샷, 질문, 후기, 정보 … (사전 JSON의 노출 카테고리 목록)
  - 브랜드 칩: 사전의 분류(스트릿·캐주얼, 미니멀 …)별 묶음, 다중 선택. 선택 시 파란색 강조.
  - 숨긴 브랜드는 흐리게(점선) 표시되고 선택 불가.
  - 선택된 브랜드의 별명을 한 줄로 표시 ("검색 포함: 스테디, 스에웨, SEW · 어나더오피스, 목동") — 새 사용자가 은어를 배우는 용도.
  - 하단: `초기화`, `N개 브랜드 · <카테고리> 보기`
- **숨기기 탭**
  - 같은 브랜드 칩 그리드, 다중 선택, 선택 시 빨간색.
  - 설명: "고른 브랜드는 게시판 목록과 검색 결과에서 보이지 않아요."
  - 하단: `모두 해제`, `저장`
- 타이핑 입력 없음. (브랜드가 많아져 찾기 어려워지면 칩 필터용 검색창은 추후 고려)

### 4.2 결과 보기
- `보기`를 누르면 **확장 프로그램 결과 페이지**가 새 탭으로 열린다 (*빌더/작성자 판단 — 팝업은 좁아 목록에 부적합*).
- 결과 페이지는 펨코 목록과 유사한 표: 탭명, 제목(원글 링크), 댓글 수, 작성자, 날짜, 조회/추천. 어떤 브랜드(별명) 검색으로 잡혔는지 작은 배지 표시.
- 선택 조건(브랜드, 카테고리)이 상단에 칩으로 보이고 그 자리에서 수정 가능하면 좋다.
- "더 보기"로 다음 페이지를 이어 불러온다.

### 4.3 평소 게시판 숨기기
- **적용 범위는 패션 게시판 한정** (사용자 결정): 패션 게시판 목록(카테고리별 포함)과 패션 게시판 검색 결과. 글 하단 목록, 메인/베스트/인기글, 링크로 직접 연 글은 대상 아님. 웹스토어 설명도 이 범위로 쓴다. (§1의 "어디서도"는 "패션 게시판 목록과 확장 프로그램 결과에서"로 읽는다.)
- 숨김 브랜드가 하나 이상이면, `fmkorea.com` 패션 게시판 목록/검색 결과 화면에서 제목에 숨김 브랜드의 별명이 포함된 `<tr>`을 숨긴다 (content script).
- 숨긴 개수를 목록 상단에 작게 표시하고 "보기"로 잠시 펼칠 수 있게 한다 (*작성자 판단 — 오탐 확인용*).
- 제목 기준이다. 본문에만 언급된 글은 평소 목록에서는 걸러지지 않는다 (검색 결과는 `!별명`으로 본문까지 제외됨).

## 5. 검색·합치기 동작

1. 선택 브랜드들의 모든 검색 별명을 모은다. 중복 제거.
2. 각 별명마다 검색어를 만든다: `<별명> !<숨김별명1> !<숨김별명2> …`
   - 사전에 브랜드별 `exclude`가 있으면 함께 붙인다 (예: 파프 → `!파프터`).
   - 검색어 길이 상한을 둔다. 넘으면 `!` 조건을 일부 생략하고, 결과 단계에서 제목 기준으로 다시 거른다.
0. **첫 구현 작업 = 검증 스파이크** (*작성자 판단*): 확장 프로그램 페이지/서비스 워커에서 사용자 쿠키를 실어 `search.php`를 fetch했을 때 보안 시스템(430)을 통과하는지, `search.php`의 `category=`가 동작하는지 실제 크롬에서 확인한다.
   - 통과하면 확장 프로그램 페이지에서 직접 요청.
   - 막히면 검색 실행을 fmkorea 탭의 content script로 옮긴다(열린 펨코 탭이 있으면 그 탭, 없으면 비활성 탭을 열어 사용 후 닫음). 이 경우 `tabs`/`scripting` 권한 추가.
3. 별명별 검색을 **순차 실행**, 요청 간 최소 1초 이상 간격 (+ 약간의 무작위 지연). 동시 요청 금지.
4. 요청은 사용자 브라우저의 fmkorea 쿠키를 포함해 보낸다 (보안 검사를 통과한 세션). 430 응답이나 보안 페이지를 받으면 즉시 중단하고 결과 페이지에 "펨코 보안 시스템 때문에 잠시 후 다시 시도" 안내.
5. 응답 HTML에서 행을 파싱 → 문서번호 기준 중복 제거 → 숨김 브랜드 제목 매칭 재필터 → 카테고리 필터 → 최신순 정렬.
6. 카테고리 지정 방법: `search.php`의 `category=` 파라미터가 동작하면 사용하고, 아니면 `td.cate` 링크의 category ID로 결과를 거른다. **빌더가 실제 브라우저에서 확인 후 결정.**
7. 결과는 조건(브랜드 집합+카테고리+숨김 집합) 키로 짧게 캐시(예: 10분)해 반복 요청을 줄인다.
8. "더 보기": 각 별명 검색의 다음 페이지를 같은 규칙으로 불러와 합친다. 자동으로 페이지를 더 불러오지 않는다 — 결과가 적어도 사용자가 "더 보기"를 누른다 (*작성자 판단*).
9. **요청 상한** (*작성자 판단*): 클릭 1회(또는 "더 보기" 1회)당 최대 12회 요청. 별명 수가 상한을 넘으면 사전의 `searchTerms` 앞쪽(대표 별명 우선) 순으로 자르고, 결과 페이지에 "별명 N개 중 12개만 검색함" 표시. 결과는 도착하는 대로 목록에 채우고, 진행 상태("4/9 검색 중")와 취소 버튼을 보여준다.

검색 대상은 기본 `title_content` (*작성자 판단*).

### 별명 매칭 (평소 목록 숨김, 결과 재필터)
- 사전의 각 별명을 정규식 패턴으로 가질 수 있다 (예: `스웨에+엑?`). 확장 프로그램 내부 매칭에만 사용하고, 펨코 검색에는 `searchTerms`(평문)를 쓴다.
- 반복 글자 정규화(“스웨에에에엑”→ 반복 축약)는 패턴으로 표현.

## 6. 사전 (공유 JSON)

- 호스팅: 공개 GitHub 저장소 **`gaeeeguri/fmfashion`**(사용자 계정, 아직 미생성 — 생성 전 사용자 확인)의 `dictionary/brands.json`, URL `https://raw.githubusercontent.com/gaeeeguri/fmfashion/main/dictionary/brands.json`. 확장 프로그램 코드도 같은 저장소. 이 URL은 웹스토어 제출 후 바꾸기 어려우므로 고정한다. 확장 프로그램 기본값으로 번들된 사본을 함께 넣어 오프라인/최초 실행에도 동작.
- 확장 프로그램은 하루 1회(및 팝업 열 때 24시간 경과 시) 원격 사전을 받아 `updatedAt`/`version`이 더 새로우면 교체. 스키마 버전이 맞지 않으면 무시하고 기존 사전 유지.
- 추후 (2) 파이프라인/크라우드소싱이 같은 파일을 갱신한다.


카테고리 칩은 여러 탭 ID를 묶을 수 있다 (`ids`). 위 묶음(착샷=착샷+베스트착샷, 후기=후기+베스트후기, 정보=패션정보+발매정보+브랜드소개, 전체=공지·이벤트·묘지 제외)은 *작성자 판단*이며 사전 JSON만 고치면 바뀐다.

초기 사전 내용(브랜드 목록·분류·별명)은 작성자(사용자)가 채운다. 빌더는 위 예시 브랜드(스테디에브리웨어, 어나더오피스, 파프터, 퍼스트플로어/퍼플, PAF)와 임의 몇 개로 시작한다.

**주의:** "목동", "퍼플"처럼 일반 단어인 별명은 오탐이 있다. 평소 목록 숨김에서 오탐은 §4.3 "숨긴 N개 보기"로 완화한다.

## 7. 사용자 설정 저장

`chrome.storage.sync`: 숨김 브랜드 ID 목록, 마지막 선택 카테고리/브랜드. 사전 캐시는 `chrome.storage.local`.

## 8. 기술 제약

- Manifest V3. 권한 최소화: `storage`, `alarms`, host `https://www.fmkorea.com/*`, 사전 호스트.
- 원격 코드 실행 금지 (웹스토어 정책) — 사전은 데이터(JSON)만.
- 웹스토어 공개용 개인정보 처리 고지: 수집/전송 없음.
- 펨코 HTML이 바뀌면 파서가 깨질 수 있다 → 파서 셀렉터를 한 곳에 모으고, 파싱 실패 시 명확한 오류 표시.

## 9. 2단계 아이디어 (이번 범위 아님)

- 사전의 `updatedAt` 이후 올라온 글을 주기적으로 수집 (자유 탭 등 제외), 토큰화 → 기존 사전과 매칭(반복 글자 정규화, 유사 철자) → 매칭 안 되는 후보는 수기 확인.
- 공개 웹에서 사람들이 후보 단어를 분류하는 크라우드소싱.
- 중앙 색인(브랜드별 글 목록 JSON)으로 전환해 클라이언트 개별 검색 제거. 펨코 JS 보안 검사 때문에 헤드리스 브라우저와 낮은 요청 속도가 필요.
