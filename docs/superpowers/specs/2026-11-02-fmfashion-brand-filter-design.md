# 펨코 패션 브랜드 필터 — 크롬 확장 프로그램 설계 (v1)

작성일: 2026-11-02 · 개정: 2026-11-03 (v1.1 — 결과를 펨코 화면 안에 표시, 병렬 요청, 캐시 제거. 바뀐 곳: §3, §4.2, §5, §7, §8, §10)

## 1. 의도와 이유

에펨코리아 패션 게시판(`https://www.fmkorea.com/fashion`)에서 브랜드는 공식 이름이 아닌 다양한 별명으로 언급된다.

- 스테디에브리웨어 → 스테디, 스에웨, SEW, 스웨에, 스웨에에에엑 …  검색 한 번으로 착샷을 다 볼 수 없다.
- 어나더오피스 → "목동" (과거 이슈에서 유래). 새로 온 사람은 이 사실을 알 수 없다.
- 파프터, 퍼스트플로어(퍼플) 등 CS 불만 글이 많은 브랜드는 보고 싶지 않은 사용자가 있다.
- "파프"(PAF)를 찾으면 "파프터"가 섞여 나와 `파프 !파프터`처럼 매번 수동 제외를 해야 한다.

**목표 경험:** 타이핑 없이 클릭만으로 "스테디에브리웨어 + 어나더오피스, 착샷 탭" 같은 조건을 고르면 그 브랜드 글이 별명과 상관없이 한 목록에 모여 보이고, 사용자가 고른 브랜드는 어디서도 보이지 않는다.

크롬 웹스토어에 공개 배포한다.

## 2. 범위

이 프로젝트는 두 부분 중 **(1) 크롬 확장 프로그램**이다.

| | 내용 | 이번 범위 |
|---|---|---|
| (1) 확장 프로그램 | 팝업 UI, 브랜드 검색/합치기, 숨기기 | ✅ |
| (2) 사전 파이프라인 | 주기적 수집 → 토큰화 → 사전 매칭 → 수기 확인, 크라우드소싱 분류 | ❌ (아이디어만 기록, §9) |

### 목표
- 사전(브랜드 → 별명 목록) 기반의 클릭형 브랜드 선택
- 여러 브랜드 동시 선택 시 **합집합(OR)** 결과를 한 목록으로
- 카테고리(탭) 지정: 착샷, 질문, 후기 등
- 사용자가 자유롭게 지정하는 숨김 브랜드
- 사전 갱신 시 확장 프로그램 재배포 불필요

### 비목표
- 사전 자동 수집/갱신 (2단계)
- 사용자 별명 제보/크라우드소싱 UI (2단계)
- 중앙 서버/색인
- 모바일 펨코, 패션 외 게시판

### 안티골 (돌아가도 실패인 것)
- 펨코 보안 시스템에 사용자 계정·IP가 차단되게 만드는 요청 패턴
- 사용자가 아무것도 고르지 않았는데 글이 숨겨지는 것 (기본 숨김 없음)
- 펨코 원래 화면을 크게 망가뜨리거나 느리게 만드는 것
- 결과를 보려고 펨코 화면을 벗어나게 하는 것 (확장 프로그램 전용 결과 페이지 없음 — 사용자 결정, v1.1)
- 브랜드를 눌렀을 때 결과가 수 초 이상 걸리는 것 ("인터넷 경험에서 7초는 너무 길어" — 사용자)
- 사용자 데이터를 외부로 전송하는 것 (사전 JSON 다운로드 외 네트워크 없음)

  ID는 변할 수 있으므로 하드코딩 대신 사전 JSON에 넣는다.
- **검색 URL**: `https://www.fmkorea.com/search.php?mid=fashion&search_target=<대상>&search_keyword=<검색어>`
  대상: `title_content`, `title`, `content`, `comment`, `nick_name`.
- **검색 문법** (사용자 확인):
  - 띄어쓰기 = **AND**
  - `!단어` = 제외 (`파프 !파프터` 동작)
  - `|` (OR) **동작 안 함** → 별명별 개별 검색 후 합쳐야 함
  - `OR`, `,`, `/정규식/`, `(a|b)` 모두 일반 검색과 동일 (사용자 확인, 2026-11-03). 정규식 지원 없음. 펨코 공지/검색 관련 글에도 띄어쓰기와 `!`만 나온다.
- **목록 HTML**: 글 하나 = `<tr>`. `td.cate > a`(탭명, href에 `category=<ID>`), `td.title > a[href="/<문서번호>"]`(제목), `a.replyNum`(댓글 수), `td.author`, `td.time`(오늘 글은 `HH:MM`, 이전은 `MM.DD`), `td.m_no`(조회, 추천). 공지 행은 `tr.notice`, 광고 행 존재. 페이지 이동은 `page=<n>`.
- **목록 구조**: 목록·검색 결과는 서버가 완성된 HTML로 보낸다. 목록용 JSON/AJAX API는 없다(페이지 스크립트 확인). 따라서 "요청 한 층 아래"를 바꿔도 한 요청으로 합집합을 얻을 수 없다.
- **페이지 수**: 목록/검색 페이지의 `form.bd_pg[data-last-page]`에 마지막 페이지 번호가 있다 (결과 없음 → `1`). 결과 0건이면 `table.bd_lst`가 없고 `div.bd_lst_wrp`만 있다.
- **`search.php`의 `category=`**: 무시된다 (사용자 확인, 2026-11-03) → 카테고리는 결과 단계에서 거른다.
- **보안 시스템 (430)**: 쿠키/JS 없는 요청(curl 등)이 몰리면 HTTP 430 + JS 확인 페이지. 브라우저 안에서의 요청으로는 아래 실험 내내 한 번도 나오지 않았다.
- **속도 제한 (429)** — 사용자 실제 크롬, 펨코 탭 콘솔에서 쿠키 포함 fetch로 측정 (2026-11-03):
  - nginx `limit_req` 형태: 본문이 nginx 기본 429 페이지, `Retry-After` 없음. 차단이 아니라 넘친 요청만 거절된다.
  - 충분히 쉰 뒤 동시 30개 → 23개 통과. 그 직후 8초 쉬고 23개/26개 → 각각 19개 통과. 429 3초 뒤 단건 → 통과.
  - 해석(추정): 버스트 용량 약 23, 재충전 초당 약 2~2.5개. IP 단위로 세어 사용자의 평소 탐색과 용량을 나눠 쓸 가능성이 높다.
  - 동시 7개 이하 묶음은 0.1~0.5초에 끝남 (첫 요청은 연결 수립으로 약 2초).

## 4. 사용자 경험

### 4.1 팝업 (툴바 아이콘 클릭)
확정 시안: `.superpowers/brainstorm/*/content/popup-v3.html` (칩 그리드 + 보기/숨기기 탭).

- 상단: 제목 "패션 브랜드 필터", 사전 버전/갱신일 표시
- **모드 탭**: `보기` | `숨기기 · N` (N = 숨긴 브랜드 수)
- **보기 탭**
  - 카테고리 칩(단일 선택): 전체, 착샷, 질문, 후기, 정보 … (사전 JSON의 노출 카테고리 목록)
  - 브랜드 칩: 사전의 분류(스트릿·캐주얼, 미니멀 …)별 묶음, 다중 선택. 선택 시 파란색 강조.
  - 숨긴 브랜드는 흐리게(점선) 표시되고 선택 불가.
  - 선택된 브랜드의 별명을 한 줄로 표시 ("검색 포함: 스테디, 스에웨, SEW · 어나더오피스, 목동") — 새 사용자가 은어를 배우는 용도.
  - 하단: `초기화`, `N개 브랜드 · <카테고리> 보기`
- **숨기기 탭**
  - 같은 브랜드 칩 그리드, 다중 선택, 선택 시 빨간색.
  - 설명: "고른 브랜드는 게시판 목록과 검색 결과에서 보이지 않아요."
  - 하단: `모두 해제`, `저장`
- 타이핑 입력 없음. (브랜드가 많아져 찾기 어려워지면 칩 필터용 검색창은 추후 고려)

### 4.2 결과 보기 — 펨코 화면 안 (v1.1)
사용자 결정: "최대한 플러그인 사이트를 사용하지 않고 펨코 화면에서 벗어나지 않았으면", "게시판 목록 자리에 합쳐진 결과가 바로 보이게". 별도 결과 페이지(`results.html`)는 없앤다.

- **진입**: 팝업 `보기` → 현재 탭이 `fmkorea.com` 탭이면 그 탭을, 아니면 새 탭을 `https://www.fmkorea.com/fashion#fmf=<상태>`로 이동시키고 팝업을 닫는다 (*작성자 판단*).
  - 상태는 주소의 `#` 뒤에 둔다: `#fmf=b:<브랜드id,…>;c:<카테고리 key>` (*작성자 판단 — 형식은 빌더 재량*). `#`이라 서버로 가지 않고, 새로고침·뒤로 가기·주소 공유 시 같은 결과가 다시 만들어진다.
  - 이미 패션 게시판 페이지에 있으면 `#`만 바뀌므로 페이지 재로드 없이 `hashchange`로 다시 실행한다.
- **결과 모드** (콘텐츠 스크립트가 패션 게시판 목록/검색 페이지에서 `#fmf=`를 보면):
  - 펨코의 원래 목록 표(`table.bd_lst`)를 그대로 쓴다. 원래 글 줄(공지 포함)은 숨기고, 검색으로 받아 온 **펨코 원본 `<tr>`** 을 같은 표에 넣는다 → 스타일·링크·아이콘이 펨코 그대로. 원래 페이지에 표가 없으면(결과 0건 페이지 등) 결과 모드 전용 빈 표를 만든다 (*빌더 재량*).
  - 각 줄 제목 칸에 어떤 별명으로 잡혔는지 작은 배지(예: `목동`, `스에웨`)를 덧붙인다.
  - 표 바로 위에 얇은 바 하나: `브랜드 모아보기` · 카테고리 · 브랜드 칩(✕로 빼기 → 주소 갱신 → 재검색) · 진행 상태(`검색 중 12/15`) · `취소` · `원래 목록으로`(`#fmf` 제거 → 원래 줄 복원, 재로드 없음).
  - 펨코 페이지 번호(`form.bd_pg`)는 숨기고 그 자리에 `더 보기` 버튼. 모든 별명이 마지막 페이지에 도달하면 버튼 대신 "끝" 표시.
  - 카테고리·브랜드를 바에서 새로 고르는 UI는 두지 않는다 — 고르는 곳은 팝업 하나 (*작성자 판단*). 바에서는 빼기만.
  - 상태 문구: 결과 0건 "조건에 맞는 글이 없어요", 429 재시도 실패 시 "펨코가 잠시 요청을 제한했어요 · 이어서 검색", 430/보안 페이지 시 "펨코 보안 확인이 필요해요. 새로고침 후 다시 시도해 주세요", 알 수 없는 페이지 시 "펨코 화면 구조가 바뀐 것 같아요".
- 결과 모드에서도 숨김 브랜드는 제외된다 (§5).
- 결과 모드 중에 숨김 설정이나 사전이 바뀌면 같은 조건으로 다시 검색한다 (*작성자 판단*).
- 결과 모드가 시작되기 전 원래 목록에 적용돼 있던 숨김 바(`#fmf-bar`)는 결과 모드 동안 치우고, `원래 목록으로` 시 다시 적용한다.

### 4.3 평소 게시판 숨기기
- **적용 범위는 패션 게시판 한정** (사용자 결정): 패션 게시판 목록(카테고리별 포함)과 패션 게시판 검색 결과. 글 하단 목록, 메인/베스트/인기글, 링크로 직접 연 글은 대상 아님. 웹스토어 설명도 이 범위로 쓴다. (§1의 "어디서도"는 "패션 게시판 목록과 결과 모드에서"로 읽는다.)
- 결과 모드가 아닐 때, 숨김 브랜드가 하나 이상이면 `fmkorea.com` 패션 게시판 목록/검색 결과 화면에서 제목에 숨김 브랜드의 별명이 포함된 `<tr>`을 숨긴다 (content script).
- 숨긴 개수를 목록 상단에 작게 표시하고 "보기"로 잠시 펼칠 수 있게 한다 (*작성자 판단 — 오탐 확인용*).
- 제목 기준이다. 본문에만 언급된 글은 평소 목록에서는 걸러지지 않는다 (검색 결과는 `!별명`으로 본문까지 제외됨).

## 5. 검색·합치기 동작 (v1.1)

1. 선택 브랜드들의 모든 검색 별명을 모은다. 중복 제거. 브랜드 간 라운드로빈 순서(각 브랜드 대표 별명이 먼저).
2. 각 별명마다 검색어를 만든다: `<별명> !<숨김별명1> !<숨김별명2> …`
   - 사전에 브랜드별 `exclude`가 있으면 함께 붙인다 (예: 파프 → `!파프터`).
   - 검색어 길이 상한을 둔다. 넘으면 `!` 조건을 일부 생략하고, 결과 단계에서 제목 기준으로 다시 거른다.
3. **요청은 펨코 탭의 콘텐츠 스크립트에서** 같은 출처 `fetch(…, { credentials: 'include' })`로 보낸다 (사용자 쿠키 그대로). 확장 페이지/서비스 워커에서 보내지 않는다.
4. **병렬 요청 + 클라이언트 토큰 버킷** (§3 측정 기반, 수치는 *작성자 판단*):
   - 페이지(탭)마다 버킷 하나: 용량 **15**, 재충전 **초당 2개**. 요청 1건 = 토큰 1개. 토큰이 있으면 즉시 보내고, 없으면 토큰이 생길 때까지 기다린다. 클릭·"더 보기"·재시도가 모두 같은 버킷을 쓴다.
   - 용량 15는 펨코 측 버스트(약 23) 중 8개 정도를 사용자의 평소 탐색 몫으로 남긴 값이다. 별명 15개 이하는 사실상 한 번에 병렬로 나간다.
   - 별도의 "요청 간 최소 1초" 순차 규칙과 `politeFetch` 대기열은 없앤다.
5. **응답 처리**
   - `200` + 목록 영역 있음 → 파싱, 합치기.
   - `429` → 그 별명만 1초 → 2초 → 4초 뒤 재시도(버킷 경유). 3번 다 실패하면 그 별명은 "남은 별명"으로 두고 나머지는 계속 진행한다. 끝나면 "이어서 검색" 제공.
   - `430` 또는 보안 페이지 → 진행 중인 모든 요청 취소, 안내 문구(§4.2). 남은 별명은 "이어서 검색"으로.
   - 그 밖의 오류/목록 영역 없음 → 해당 별명 실패로 표시하고 나머지는 계속. 하나라도 "목록 영역 없음"이면 "화면 구조가 바뀐 것 같아요" 안내.
6. 응답 HTML에서 행을 파싱 → 문서번호 기준 중복 제거(배지는 누적) → 숨김 브랜드 제목 매칭 재필터 → 카테고리 필터(`td.cate` 링크의 category ID; `search.php`의 `category=`는 무시되므로 쓰지 않음) → 최신순(문서번호 내림차순) 정렬. 결과는 도착하는 대로 표에 반영한다.
7. **캐시 없음** (사용자 결정). 새로고침/뒤로 가기 시 다시 검색한다. (브라우저 bfcache가 페이지를 그대로 복원하면 그대로 둔다.)
8. "더 보기": 아직 마지막 페이지(`data-last-page`)에 닿지 않은 별명만 다음 페이지를 같은 규칙으로 병렬로 불러와 합친다. 자동으로 더 불러오지 않는다.
9. **요청 상한** (*작성자 판단*): 클릭 1회(또는 "더 보기" 1회)당 최대 **30**개 별명. 넘으면 라운드로빈 순서 앞쪽만 검색하고 바에 "별명 N개 중 30개만 검색" 표시. (15개 초과분은 버킷 재충전 속도로 이어서 나간다.)
10. 취소/조건 변경: 새 실행이 시작되면 이전 실행의 진행 중 요청을 `AbortController`로 취소하고, 이전 실행의 늦은 응답은 무시한다.

검색 대상은 기본 `title_content` (*작성자 판단*).

### 별명 매칭 (평소 목록 숨김, 결과 재필터)
- 사전의 각 별명을 정규식 패턴으로 가질 수 있다 (예: `스웨에+엑?`). 확장 프로그램 내부 매칭에만 사용하고, 펨코 검색에는 `searchTerms`(평문)를 쓴다.
- 반복 글자 정규화(“스웨에에에엑”→ 반복 축약)는 패턴으로 표현.

## 6. 사전 (공유 JSON)

- 호스팅: 공개 GitHub 저장소 **`gaeeeguri/fmfashion`**(사용자 계정, 아직 미생성 — 생성 전 사용자 확인)의 `dictionary/brands.json`, URL `https://raw.githubusercontent.com/gaeeeguri/fmfashion/main/dictionary/brands.json`. 확장 프로그램 코드도 같은 저장소. 이 URL은 웹스토어 제출 후 바꾸기 어려우므로 고정한다. 확장 프로그램 기본값으로 번들된 사본을 함께 넣어 오프라인/최초 실행에도 동작.
- 확장 프로그램은 하루 1회(및 팝업 열 때 24시간 경과 시) 원격 사전을 받아 `updatedAt`/`version`이 더 새로우면 교체. 스키마 버전이 맞지 않으면 무시하고 기존 사전 유지.
- 추후 (2) 파이프라인/크라우드소싱이 같은 파일을 갱신한다.

## 7. 사용자 설정 저장

`chrome.storage.sync`: 숨김 브랜드 ID 목록, 마지막 선택 카테고리/브랜드. 사전 캐시는 `chrome.storage.local`. 검색 결과는 저장하지 않는다 (v1.1, 캐시 없음).

## 8. 기술 제약

- Manifest V3. 권한 최소화: `storage`, `alarms`, host `https://www.fmkorea.com/*`, 사전 호스트. `tabs` 권한은 쓰지 않는다 — 팝업은 `chrome.tabs.query`/`update`/`create`만 쓰고, fmkorea 탭의 URL은 host 권한으로 보인다.
- 콘텐츠 스크립트는 사전을 서비스 워커 메시지(`getDictionary`)로 받는다 (기존과 동일).
- 원격 코드 실행 금지 (웹스토어 정책) — 사전은 데이터(JSON)만.
- 웹스토어 공개용 개인정보 처리 고지: 수집/전송 없음.
- 펨코 HTML이 바뀌면 파서가 깨질 수 있다 → 파서 셀렉터를 한 곳에 모으고, 파싱 실패 시 명확한 오류 표시.

## 9. 2단계 아이디어 (이번 범위 아님)

- 사전의 `updatedAt` 이후 올라온 글을 주기적으로 수집 (자유 탭 등 제외), 토큰화 → 기존 사전과 매칭(반복 글자 정규화, 유사 철자) → 매칭 안 되는 후보는 수기 확인.
- 공개 웹에서 사람들이 후보 단어를 분류하는 크라우드소싱.
- 중앙 색인(브랜드별 글 목록 JSON)으로 전환해 클라이언트 개별 검색 제거. 펨코 JS 보안 검사 때문에 헤드리스 브라우저와 낮은 요청 속도가 필요.
